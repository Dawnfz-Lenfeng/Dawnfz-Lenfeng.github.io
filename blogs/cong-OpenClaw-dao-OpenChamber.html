从 OpenClaw 到 OpenChamber

毕业前那阵子，我给自己写了个约教室的小工具，让 AI 每天自动帮我抢。每天凌晨一点准时约一间。约来的教室一般就在立德楼，我和对象常溜过去，在里面打游戏。现在还会想起以前在群里约好教室、几个人凑一块打游戏的时光，也挺怀念的。

其实这预约功能说白了就是 Linux 的定时任务加脚本，离了 AI 也能跑。真正有意思的是逆向那部分——一开始是我自己摸索，在浏览器里开开发者工具抓包，一点点搞明白的，也算是学了个小技能。现在 AI 变强了，我直接丢给它去做，它自己会搜、自己会看，基本全包了。

《暑假小记》里说过打算毕业了就开源，现在确实开源了，不过没什么人理。想想也正常，人大的理工氛围太淡，大多数同学都是文科生，就算开源了，愿意折腾的人也没几个。

1. 新方向

最近这段时间，主要在接触客户端、前端这些，还有网页 APP 的开发，收获不小。

TypeScript 和 React 都挺有意思，尤其 TS，写起来很舒服。我早就有个愿望，想要一门语法类似 Rust 的脚本语言，没想到 TS 差不多就把这个需求满足了。它那个类型系统尤其对我胃口——写代码像在定义数据结构，写到后面心里很清楚，不会迷失。

2. 从 OpenClaw 到 OpenChamber

最让我意外的还是 OpenChamber，是在 X 上无意刷到的。那平台确实不错，观点多、更新也快。抱着试试的心态用了一下，结果就停不下来了：在手机上就能直接跟它对话、改服务器上的文件，太方便了。可以说就是因为它，我才把之前的 AI 彻底换掉。

经过这些事，我最大的体会是：遇到新东西，一定要第一时间去试。试得越早，越早吃到红利，等大家都用上了，就轮不到你尝鲜了。就拿 Codex 举例，它刚火的时候我也心动过，但当时觉得用 opencode 配个模型也能干个七八成，就没去试。后来真用上才发现，完全不是一回事，性价比也高，挺后悔没早点动手。以后看到新东西，我决定直接上，不纠结。

至于被换掉的那位，写了这么久代码回头看，它确实写得不怎么样。连 QQ、微信这些对接都要手动去适配，实在有点蠢。相比之下，opencode 原生就支持服务端，用 web 技术天然就能远程控制，想怎么做都行。我觉得，这才是软件开发本该有的样子。

这篇写到这里也差不多该收了。博客还是想接着写，哪怕以后都是手机上一段一段口述出来的。希望读博的日子别太忙，还能让我把这些流水账一直记下去。
